## 上下文

实际上游为官方 `deepseek-flash`，`/models` 返回 `context_window=1048576`、`max_output_tokens=393216`；对应 [官方模型元数据说明](https://api-docs.deepseek.com/api/list-models/)。工作窗口选 **131072**，输出预留仍为 **8192**，没有直接用满 1M。

- proactive compression 条件：输入消息估算 + 工具定义估算 + 输出预留 > context_window。
- 该硬检查没有另外的比例参数；128K 下输入有效预算为 122880。
- 后台摘要有独立的 `summarize_token_percent=65` 和消息数阈值。比例按 context_window 计算，当前摘要 token 阈值为 85196，消息数阈值继续为 100000。

用近期真实历史的 82 条消息作为隔离 CLI 会话种子，连续 **40 轮回放**与 **8 轮真实模型内部会话**均无 proactive compression 告警。真实模型验收使用短的非思考回复，验证接续及请求可承载性；不是正常思考模式的延迟基准，也没有向 Telegram 刷测试对话。真实用户会话文件未被测试脚本写入。主服务上线后核对到的日志同样为 0 次该告警，长期自然聊天表现仍需继续观察。
